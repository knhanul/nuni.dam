# 구현 구조

## 실행 흐름

사진 선택 / QR 요청 / SAF 폴더 동기화가 `PhotoStore`의 동일한 가져오기 경로를 사용합니다. 직렬 잠금 안에서 입력 크기 확인 → 임시 파일 → SHA-256 중복 확인 → 이미지 크기만 디코딩 → 다운샘플링 → EXIF 방향 보정 → JPEG 임시 저장 → 용량 확인 → Palette·ML Kit 분석 → 파일명 확정 → Room 등록을 진행합니다.

`.part` 파일은 등록 전에 완성하고 fsync합니다. 파일·DB 사이에는 단일 트랜잭션을 사용할 수 없으므로, 비정상 종료로 생긴 미참조 파일은 하루가 지난 뒤 정리합니다. 원본 URI에는 쓰지 않습니다. 가져오기 임시 원본은 완료·실패 시 삭제하고, 전날 남은 임시 파일은 시작 시 정리합니다.

`FrameSession`이 사진 순서·문구·타이머·현재 사진을 관리하고 `FrameView`가 Canvas에 그립니다. Activity와 DreamService가 같은 세션·뷰를 사용합니다. 화면 생명주기가 끝나면 핸들러, 리스너, 디코딩 실행기를 해제합니다. 오래된 비동기 결과는 세대 번호로 무시합니다.

## 메모리·전력 기준

입력은 최대 40 MiB, 이미지 픽셀 수는 최대 1억 6천만으로 제한합니다. 원본 전체 비트맵을 먼저 만들지 않고 긴 변 2048px/1280px 이하의 power-of-two 샘플을 선택합니다. 따라서 원본 비율에 따라 FHD보다 작게 저장될 수 있습니다. 색상 분석은 작은 축소판을 사용합니다. 얼굴 분석 작업이 타임아웃되더라도 ML Kit가 끝나기 전 그 작업의 비트맵을 해제하지 않습니다.

보관함 썸네일 메모리 캐시는 4 MiB입니다. 브라우저 썸네일은 24장씩 페이지를 나누고 동시 두 건씩 요청합니다. 액자는 단일 이미지 디코더를 사용합니다. 본문 줄 배치는 캐시하고 시간·달력 문자열은 분 단위로 갱신합니다. 확대 중 약 25fps로 다시 그리며 저사양·야간·일시 정지 때 연속 애니메이션을 중단합니다. 기기별 GPU/메모리 사용량은 실제 기기에서 측정해야 합니다.

## 동기화 정책

선택한 폴더의 바로 아래 이미지만 읽습니다. 하위 폴더 재귀 탐색은 하지 않습니다. `documentId`, 수정 시각, 크기가 같으면 재가져오기를 생략합니다. 제공자가 시각·크기를 주지 않으면 내용을 다시 읽고 해시로 중복을 확인합니다.

6시간 WorkManager 실행은 정확한 시각 예약이 아닙니다. OS 절전·작업 정책에 의해 지연될 수 있습니다. 로컬 폴더를 오프라인에서도 읽을 수 있도록 네트워크 제약은 걸지 않았습니다. 원격 API 어댑터를 추가하면 해당 Worker에 `UNMETERED` 네트워크 조건을 별도로 두세요.

전체 목록을 성공적으로 읽은 뒤, 현재 선택 폴더가 그대로인지 확인하고 삭제 반영을 한 번의 Room 트랜잭션으로 처리합니다. 오류/중단/부분 목록/빈 폴더에서는 삭제를 적용하지 않습니다. 누락된 원본 참조가 모두 없어도 `owned` 또는 `favourite` 사진은 보호합니다. 목록 완전성이 보장되지 않는 원격 제공자는 삭제 연동을 끈 채 사용해야 합니다.

## QR 세션과 API

`TransferActivity`가 보이는 동안만 IPv4 사설망 HTTP 서버를 엽니다. 임의 포트와 192비트 토큰을 생성합니다. 토큰은 QR URL의 fragment에 넣고 페이지 로드 뒤 주소창에서 지웁니다. API 요청은 `Authorization: Bearer …`를 사용합니다. 토큰은 브라우저 영구 저장소에 쓰지 않습니다.

첫 인증 상태 확인이 태블릿 승인 창을 띄웁니다. 승인은 이 토큰을 소지한 **세션 전체**에 적용되며 개별 브라우저 인증서에 묶인 것은 아닙니다. QR을 다른 사람에게 공유하면 동일한 접근 권한을 줄 수 있습니다. 새 QR 생성·화면 이탈·만료로 이전 연결을 끝낼 수 있습니다.

| API | 방식 | 내용 |
|---|---|---|
| `/` | GET | 관리 HTML. 사진·비밀 정보는 없는 초기 페이지 |
| `/api/status` | GET | 토큰 확인, 승인 요청, 남은 시간 |
| `/api/photos` | GET | 활성 사진 메타데이터, 사용량·상한 |
| `/api/image?id=…` | GET | 인증된 320px JPEG 썸네일 |
| `/api/upload?name=…` | POST | 원시 이미지 body, Content-Length 필수, 최대 40 MiB |
| `/api/photo` | POST JSON | `id`와 `action`: `note`, `favourite`, `trash` |
| `/api/settings` | GET | 비밀 정보가 없는 내보내기 설정 |
| `/api/settings` | POST JSON | `mode`, `theme`, `seconds`, `brightness`, `phrase`만 수정 |

JSON body는 8 KiB로 제한합니다. 길이가 잘린 업로드와 chunked 전송은 거절합니다. 별도 사용자 입력 경로를 파일 경로로 사용하지 않고 해시 이름만 사용합니다. 다른 Origin은 거절하며 캐시 방지·프레임 금지·CSP 헤더를 둡니다. 전송 암호화와 인터넷 원격 연결을 제공하는 설계는 아닙니다.

## 확장 순서

1. 실제 Android 6~16 기기에서 설치·수명 주기·메모리·72시간 구동을 검증합니다.
2. 핵심 화면과 데이터 계층 사이의 인터페이스를 분리하며 규모에 맞게 패키지를 나눕니다.
3. 외부 서비스 어댑터, 인증 정보 보관, 재시도·목록 완전성 계약을 추가합니다.
4. Google Play 결제 검증·복원과 유무료 정책을 결합합니다.
5. 일정·폰트·조도 센서·전용 기기 관리 기능은 각각 권한·기기 지원 검사를 둡니다.

Room version 1 이후에는 Migration을 명시적으로 작성하고 실제 구버전 DB로 시험하세요. 사진을 지우는 파괴적 마이그레이션은 사용하지 않습니다.
