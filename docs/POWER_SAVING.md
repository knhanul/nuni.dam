# 주변 감지에 따른 절전 및 화면 제어 사양 (`docs/POWER_SAVING.md`)

## 1. 개념 구분과 제품 원칙

누니담은 감지 능력과 절전 수준을 과장하지 않고 다음 개념을 엄격히 구분합니다.

1. **움직임 감지 (`CAMERA_MOTION`)**: 전면(또는 기본) 카메라의 저해상도 밝기(Y) 채널 프레임 간 변화량을 계산합니다. 정지해 있는 사람의 재실 여부나 미터(m) 단위의 거리를 측정하지 않으므로 사용자 옵션명을 **‘주변 움직임에 반응’**으로 표기합니다.
2. **근접/조도 센서**:
   - 조도 센서(`TYPE_LIGHT`)는 주변 밝기 진단 정보로 표시하며, 어둡다는 이유만으로 사람이 없다고 판정하지 않습니다.
   - 근접 센서(`TYPE_PROXIMITY`)는 기기별 최대 범위(대개 5~8cm 또는 near/far)와 wake-up 속성을 진단 화면에 그대로 표시하며, 1~3m 원거리 사람 감지기로 취급하지 않습니다.
3. **감광 (`DIMMED`) vs 실제 화면 꺼짐 (`SCREEN_OFF`)**:
   - **감광 (`DIMMED`)**: 창 밝기를 최저(`0.01f`)로 낮추고 어두운 오버레이(`잠시 쉬는 중 · 화면을 터치하면 밝아집니다.`)를 표시하며, 사진 확대 애니메이션과 슬라이드 전환 타이머를 중단합니다. 모든 지원 기기에서 동작하며 터치 또는 움직임 감지로 즉시 복귀합니다.
   - **실제 화면 꺼짐 (`SCREEN_OFF`)**: `Display.STATE_OFF`로 실제 디스플레이 전원이 꺼진 것이 관찰되고, 화면이 꺼진 상태에서도 감지/복귀 경로가 실증된 환경(`screenOffWakeVerified == true`)에서만 활성화합니다. 단순 `FLAG_KEEP_SCREEN_ON` 해제 요청이나 미검증 기기에서는 `SCREEN_OFF`로 허위 기록하지 않고 안전한 감광(`DIMMED`)을 제공합니다.

## 2. 런타임 기능 진단 (`PowerSaving.DeviceCapabilities`)

앱 실행 및 설정 진입 시 다음 항목을 런타임에 검사하여 **`지원 / 설정 필요 / 미지원 / 아직 검증되지 않음`**으로 분류합니다.

- Android API 레벨, 전면/후면 카메라 존재 여부, `Manifest.permission.CAMERA` 허용 상태
- 조도 센서(`TYPE_LIGHT`) 및 근접 센서(`TYPE_PROXIMITY`) 존재·최대 범위·해상도·`isWakeUpSensor()` 여부
- 감광 지원 여부(항상 지원) 및 화면 꺼짐 후 자동 복귀 검증 상태(`screenOffWakeVerified`: 실기기 하드웨어 검증 전까지 기본 `false`)

새 설치 시 `motionEnabled` 기본값은 **`false`(OFF)**이며, 사용자가 설정에서 기능을 켜고 권한 허용 및 **10초 동작 확인**을 거치도록 안내합니다.

## 3. 절전 상태 제어기 (`Core.PowerSavingStateMachine`)

화면마다 개별 타이머를 두지 않고 순수 Java로 테스트 가능한 단일 상태 제어기(`Core.PowerSavingStateMachine`)를 통해 상태를 결정합니다.

### 3.1 상태 정의

| 상태 | 의미 | 동작 |
|---|---|---|
| `ACTIVE` | 정상 표시 중 | 주간 설정 밝기, 사진 슬라이드쇼 및 확대 애니메이션 재생 |
| `IDLE_PENDING` | 부재 대기 구간 | 마지막 유효 활동 후 부재 시간의 50%~100% 경과 구간. 새 활동 감지 시 즉시 `ACTIVE` 복귀 |
| `DIMMED` | 감광 중 | 밝기 `0.01f`, 검은 오버레이, 사진 전환·애니메이션 중지. 터치 또는 움직임으로 `ACTIVE` 복귀 |
| `SCREEN_OFF` | 실제 화면 꺼짐 확인 | `Display.STATE_OFF` 관찰 및 복귀 검증 시에만 진입 |
| `UNAVAILABLE` | 감지 경로 사용 불가 | 카메라 미지원 또는 권한 거부/철회. 이유를 안내하고 시간표·터치 기반 기본 절전으로 동작 |

### 3.2 상태 전이 및 운영 규칙
- **최소 유지 시간 (`MIN_HOLD_MS = 30,000ms`)**: 화면이 깨어난 뒤 최소 30초 동안은 `ACTIVE`를 유지하여 깜빡임(hunting)을 방지합니다.
- **이벤트 디바운스 (`DEBOUNCE_MS = 1,500ms`)**: 짧은 반복 움직임 이벤트를 중복 제거합니다.
- **작업 중 절전 억제 (`inhibited`)**: 전체 화면에서 제어 메뉴가 열려 있거나, 사진을 편집·가져오기 중이거나, QR 전송 화면(`TransferActivity`)이 열려 있을 때는 부재 절전으로 화면을 어둡게 하거나 끄지 않습니다.
- **야간 시간표 우선**: 야간 시간대에는 기본적으로 움직임으로 화면을 밝히지 않고 `DIMMED`를 유지합니다. 사용자가 **‘야간 쉬는 시간에도 움직임에 반응해 잠시 밝히기’(`nightReact`)**를 켠 경우에만 야간 움직임 시 잠시 밝힙니다. 사용자가 화면을 직접 **터치**하면 야간이라도 60초 동안 조작 가능한 밝기(`ACTIVE`)를 제공합니다.
- **오류·권한 철회 안전 처리 (`UNKNOWN` / `ERROR` / `PERMISSION_DENIED`)**: 카메라 점유나 오류 발생 시 이를 ‘사람 부재’로 오인하여 즉시 화면을 어둡게 하지 않고 현재 표시 상태를 유지하며 진단에 기록합니다.

## 4. 카메라 밝기 변화 감지 (`PowerSaving.CameraMotionSource`)

- **해상도 및 분석 주기**: `320×240` `YUV_420_888` 스트림에서 Y(밝기) 평면만 읽어 약 `2 fps`(`480ms` 간격)로 분석합니다. 얼굴 검출 ML Kit 모델을 상시 구동하지 않습니다.
- **큐 관리 및 개인정보 보호**: `ImageReader.acquireLatestImage()`(maxImages=2)로 최신 프레임만 유지하고 `finally` 블록에서 항상 `Image.close()`를 호출합니다. 영상은 기기 메모리에서만 비교 후 즉시 폐기하며 파일 저장·네트워크 전송을 일절 수행하지 않습니다.
- **전체 조명 변화 보정 및 관심 영역 (`Core.lumaMotionScore`)**:
  - 사용자가 지정한 관심 영역(`ROI`: `roiLeft`, `roiTop`, `roiRight`, `roiBottom`, 기본 `10%~90%`) 내부 픽셀만 계산하여 창문·TV·커튼 영역을 제외할 수 있습니다.
  - 이전 프레임과 현재 프레임의 ROI 평균 밝기 차이(`meanShift`)를 먼저 차감하여 카메라 자동 노출(AE)이나 액자 화면 빛 반사로 인한 전체 밝기 변화 오탐을 억제합니다.
  - 연속 2회 이상 임계치를 넘을 때만 유효 움직임으로 확정합니다.
- **10초 동작 확인 UI**: `설정 → 화면과 절전 → 10초 동작 확인 시작`에서 실시간 Y 채널 미리보기, ROI 사각형, 변화율(%), 감지 여부를 10초간 보여준 뒤 카메라를 자동으로 닫습니다.

## 5. 절전 에너지 모델과 실측 주의사항

하루 절감 에너지는 다음 수식으로 설명됩니다:

```text
절감량(Wh/일) = (화면 ON 전력 - 감광/OFF 전력) × 감광/OFF 시간 - 감지 기능 추가 소비 전력
```

- 카메라 분석 주기를 2fps로 낮추더라도 카메라 센서와 ISP 세션을 열어두면 기기에 따라 추가 전력이 발생합니다.
- 실제 전력계(Wh) 측정값이 없는 상태에서 임의의 절감률(%)을 표시하지 않으며, 진단 화면에는 실제 누적 체류 시간(표시 분 / 감광 분 / 꺼짐 분)과 이벤트 횟수만 기록하고 **`절감량은 아직 측정하지 않았어요.`**로 명확히 안내합니다.
